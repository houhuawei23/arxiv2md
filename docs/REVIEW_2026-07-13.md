> 评审视角：Python 架构师 / 系统设计师

## 一、项目概览与设计意图

**定位**：arXiv 论文 → Markdown 转换工具，支持图片下载/插入、HTML 与 LaTeX 双解析模式、元数据富化（Crossref/OpenAlex/TeX 机构信息）、结构化 JSON 导出。

**设计意图**：从"双管线（Legacy BS4 序列化器 + Pandoc 后处理）"向"**IR 三层架构统一管线**"（Builder → Transform → Emitter）迁移。`docs/old_OPTIMIZATION_PLAN.md` 原计划 v1.0.0（3-4 周）内完成 legacy 私有移除。

**实际状态**：迁移停在半途。v0.10-0.12 完成了 ImageResolver 统一、Orchestrator 提取、异常体系、BS4 优化、footnote deque；但 **v1.0.0 的 legacy 移除（删 `format_paper`/`structured_export`/`_legacy_blocks`/`--legacy`）未执行**，且在停滞期间又积累了新债务（`ir_pipeline.py` 死代码、orchestrator 私有符号耦合、3 重后处理）。

## 二、架构与数据流程分析

### 2.1 四种输入模式 × 两条管线（核心事实）

| 输入模式 | 入口 | 实际管线 | 状态 |
|---|---|---|---|
| 远程 arXiv HTML（默认） | `IngestionOrchestrator` | **IR**（HTMLBuilder → PassPipeline → MarkdownEmitter/JsonEmitter） | ✅ IR |
| 远程 arXiv LaTeX | `ingestion/latex.py` | **Legacy**（pandoc → `latex/parser.py` 1989 行 → `format_paper` → `structured_export`） | ❌ 未迁移 |
| 本地 HTML 文件 | `ingestion/local_html.py` | **Legacy**（`convert_fragment_to_markdown` + `format_paper`） | ❌ 未迁移 |
| 本地归档（TeX） | `ingestion/local.py` | **Legacy**（同 LaTeX） | ❌ 未迁移 |

**结论**：IR 三层架构目前**只服务 1/4 输入模式**。`LaTeXBuilder`（878 LOC）已实现但生产路径不走它——LaTeX 仍用 pandoc + legacy formatter。`ir_pipeline.py`（196 LOC）封装了"干净的 IR 组合 API"（`build_document_from_html`/`build_document_from_latex`/`create_default_pipeline`），**但 0 调用者**——orchestrator 直接内联了 Builder/Pass/Emitter，绕过它。

### 2.2 默认 IR 路径的 3 重后处理（关键异味）

`IngestionOrchestrator._emit_markdown` 对一份 markdown 连续做 3 遍清洗：

1. `MarkdownEmitter._post_process`（emit 内部）：`re.sub(r"\n{3,}", "\n\n", md)` + 逐行 rstrip
2. `output/formatter._format_markdown_output`（orchestrator:397 调用，**legacy 私有函数**）：锚点、表格标题、display-math、重复 bullet、空行
3. `output/markdown_postprocess.clean_markdown_output`（output_finalize:193 调用）：剥 `<a id>`、清 LaTeX 数学、`$x$` 间距

LaTeX 路径还有第 4 重 `_postprocess_markdown_enhanced`。

**诊断**：Emitter 按构造就是不完整的——它产出的 markdown 必须再被 legacy 正则修补。锚点/数学/空行在 3 个阶段被重叠处理，顺序敏感、无法整体推理。这是"迁移半途"最直接的证据。

### 2.3 设计上做对的部分（需保留）

- **IR 数据层类型健全**：Pydantic v2 discriminated union（`Annotated[A|B|..., Field(discriminator="type")]`），`extra="forbid"`，无 mutable default 共享。
- **分层干净**：Builder 封装所有 BS4/Pandoc；Transform 是纯 IR（无 HTML 泄漏）；Emitter 直接走 IR 不回 parse。
- **异常体系设计良好**：`Arxiv2mdError` 带 `exit_code`，10 个子类，语义清晰。
- **图片异步路径设计良好**：`process_images_async` 用 `ProcessPoolExecutor` + `finally` shutdown + 信号量限流——是 citations 应模仿的范式。
- **配置系统分层完整**：CLI > env > YAML > profile > default，`deep_merge` 可控。

### D. 类型安全缺口（静默数据丢失风险）

- **Visitor**（`ir/visitor.py:75-81`）：`getattr(self, f"visit_{node.type}", None)` 字符串派发——新增节点类型无 `visit_<type>` = 静默 no-op。
- **MarkdownEmitter**（`ir/emitters/markdown.py:90-167`）：字符串 if/elif + `getattr` 兜底 + 末尾 `return ""`——新增 union 成员无分支 = 静默丢弃。`PlainTextEmitter` 用 isinstance（正确），应统一。
- **`_CHILD_SPECS`**（`visitor.py:40-63`）：手维护 dict 与 Pydantic 定义重复——新容器节点未注册 = `walk()` 静默跳过子节点。
- **7 模块 `mypy ignore_errors`**：`output.formatter`、`output.metadata`、`output.structured_export`、`html.serializers.*`、`latex.structured`、`ir._legacy_blocks`、`citations.html_parser`——恰好是 legacy/重复面。

### E. 异步/性能

- **sync CPU 密集塞 async**：`orchestrator.run()` 内 `_parse_html`/`_build_ir`/`_run_transforms`/`_emit_markdown` 全同步未 `to_thread` → batch 在 CPU 阶段退化为串行。
- `_save_paper_yml`(async) 调 sync `save_paper_metadata`。
- `local.py`：tarfile 解压、`read_text`、`shutil.copy2` 在 async 内同步。
- **HTTP client 永不关闭**：无 `aclose`/`atexit`；`is_closed` 自愈分支是死代码；跨 loop 复用未检测。
- **重试不一致**：arXiv/Crossref 有重试；OpenAlex + abs-HTML 单发无重试。
- `batch --max-concurrency` 在 `--continue-on-error=False` 时被忽略。

### F. 耦合

- **orchestrator 跨边界导 legacy 私有符号**：`from output.formatter import _format_markdown_output, _format_token_count, _create_sections_tree, count_sections`。
- **orchestrator 摸 ImageResolver 私有属性**：`_stem_map` / `_index_map`。
- `formatter._format_markdown_output` 函数内 import `html.markdown._simplify_display_math`。
- `utils/progress.py` 模块级 `_console` → network/latex 层依赖 Rich。
- settings 进程级可变单例 `_SETTINGS` + `set_settings`。

### G. 错位/命名

- `utils/html_attrs.py`（HTML 专用，应在 `html/`）；`utils/aiofiles_compat.py`（非 compat shim）；`utils/metrics.py`（仅 timing，应 `timing.py`）。
- `images/resolver.py` 应 `processor.py`。
- `cli/runner/base.py` 无 base class。
- `ir/_legacy_blocks.py` 在 `ir/` 下却产出 `schemas.structured.BlockJson`。

## 五、重构方案（破坏性，目标架构）

### 5.1 设计原则

1. **IR-First 单管线**：4 种输入模式统一走 `Builder → PassPipeline → Emitter`。
2. **Emitter 拥有最终输出**：markdown 只在 emit 内做一次后处理；数学/锚点在 IR 构建时清理。
3. **不可变 IR 数据流**：Pass 返回新对象或显式 deepcopy，而非就地变异。
4. **类型安全的派发**：Visitor/Emitter 用 `isinstance` 或 `singledispatch`；未知类型 raise。
5. **显式优于全局**：settings 显式传入；HTTP client 用 `async with` 生命周期。
6. **一个事实来源**：`ConvertParams` 用 `dataclasses.replace` 派生；一个结构化导出器；一个 section 过滤语义。

### 5.2 目标目录结构（删减后）

```
src/arxiv2md_beta/
├── cli/                    # 仅参数解析 + 委派（薄）
│   ├── app.py
│   ├── params.py           # ConvertParams（唯一字段来源）
│   └── runner/
├── ingestion/

│   ├── sources/            # html.py / latex.py / local.py（仅"取源"）
│   └── pipeline.py         # ingest_paper 公共 API（薄委托）
├── ir/                     # 三层（保留，清理）
```

## 六、重构与改进计划（分阶段执行）

### Phase 0 — 安全网（先做）
- 固定 markdown 输出为 golden snapshot（HTML + LaTeX + local 各一）。
- 测试基线：pytest 1 fail/382 pass（pre-existing schema-drift）、ruff 7 err、mypy 17 err。
- 回归 oracle：测试数不下降 + lint 不退化。

### Phase 1 — 修真实 Bug（高 ROI，低风险）
1. **A1**：`merge_convert_params` → `dataclasses.replace(template, input_text=...)`。
2. **A4**：`extract_arxiv_images` → `await asyncio.to_thread(process_images, ...)`。
3. **A5**：sync `process_images` except 加 `ImageProcessingError`。
4. **A2**：删 orchestrator 第二次 `_parse_html()`。
5. **A3**：`async with asyncio.TaskGroup()` 或 try/finally cancel。
6. **A6**：`AnchorPass` 遍历 `doc.abstract` + `front_matter`。
7. **A7**：`figure_reorder` 正则 → `Fig(?:ure)?\.?\s*(\d+)`。
8. **A8**：`CitationResolver` 加 `Semaphore(6)`。
9. **A9**：TeX 解压 `try/except/finally rmtree`。
10. **A10**：18 处裸 raise → `exceptions.*Error` 子类；加 ruff `TRY003`/`BLE001`。
11. **A12/A13/A14**：LaTeX builder 修正。

### Phase 2 — 删死代码（减负）
1. 删 `ingestion/html.py`、`ingestion/ir_pipeline.py`、`html/serializers/`。
2. 删 `--legacy` flag。
3. `cache/result_cache.py`：接入或删。

### Phase 3 — 解耦 IR 与 legacy
1. 抽 `formatter` 私有 → `output/markdown_utils.py`。
2. 数学简化移到 IR 构建时；其余并入 `MarkdownEmitter._post_process`。
3. orchestrator 不再 import formatter 私有符号。
4. 合并 3 重后处理为 1 重。
5. 抽 `ImageResolver.iter_assets()` 公共访问器。

### Phase 4 — 统一结构化导出
1. `JsonEmitter` 覆盖 `structured_export` 全契约。
2. 删 `output/structured_export.py` + `ir/_legacy_blocks.py`。
3. `latex/structured.py` 改用 `JsonEmitter`。
4. 统一 section 过滤语义。

### Phase 5 — LaTeX + Local 迁移到 IR（最大块）
1. LaTeX 走 `LaTeXBuilder` → PassPipeline → MarkdownEmitter。
2. Local HTML 走 `LocalHtmlBuilder` → 同管线。
3. Local archive 复用 LaTeX IR 路径。
4. 删 `html/markdown.py`、legacy local 逻辑。

### Phase 6 — 类型安全 + 数据模型收敛
1. Visitor / MarkdownEmitter 改 `isinstance` 派发；未知 raise。
2. `_CHILD_SPECS` 改 Pydantic 字段内省。
3. Pass 改不可变。
4. `schemas/` 与 `ir/` 重复模型归并或文档化。
5. `ConvertParams` 单一来源。

### Phase 7 — async/性能 + 收尾
1. orchestrator 重 CPU 步骤 `to_thread`。
2. `_save_paper_yml`、local sync I/O → `to_thread`。
3. `network/http.py` 加 `close_http_client()` + 生命周期。
4. OpenAlex + abs-HTML 接入重试。
5. `batch` 两路径都并行。
6. `utils/` 瘦身 + 重命名。
7. 全量 `ruff` + `mypy`（目标 0 ignore_errors）。

### Phase 8 — 文档与回归
1. 重写 `docs/pipeline.md`。
2. 新 `docs/architecture.md`。
3. LaTeX 真实论文集成测试。
4. 性能回归：P50 < 5s。

### Phase 5 收尾 — LaTeX IR Builder 质量对齐（2026-07-13）

以真实论文 1706.03762（Attention Is All You Need）为测试用例，对比 LaTeX（`--parser latex`）与 HTML（`--parser html`）输出。修复 6 个准确性问题，使 LaTeX 输出与 ar5iv HTML 输出一致：

| 问题 | 修复 |
|---|---|
| 引用格式不一致（`[[35, 2, 5]]` vs `[[35], [2], [5]]`） | Cite handler 每个引用号独立 `[N]` inline + `target_id` |
| `\paragraph` 标题不应编号（`##### 3.1.1 Encoder:`） | `SectionNumberingPass` 跳过 `level>=5` |
| References 纯段落 vs bullet list | thebibliography → `ListIR(ordered=False)` |
| `\bibitem[10]{key}` 标签泄漏为 stray `- 10` | 过滤纯数字段落 |
| Acknowledgements 被丢弃 | thebibliography 处理前 flush pending section |
| 无扩展名 image src 无法解析 | `_resolve_image_src` 探测 `base_dir` 常见扩展名 |

修复后 HTML/LaTeX 输出对齐：heading 结构相同（8 h2 / 12 h3 / 3 h4 / 5 h5）、引用格式 `[[N]]` 双括号、References `- ` bullet list、sidecar 分割正常。版本更新至 0.13.0。
