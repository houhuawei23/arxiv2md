## 〇、一句话结论

项目已完成"IR 三层架构"作为**中间表示**的统一（4 种输入都走 `Builder → PassPipeline → Emitter`），但**编排（orchestration）从未统一**：4 条输入路径各自手写一遍"取源 → 建 IR → 跑 pass → emit → 后处理 → 存盘 → 导出"的同一序列，并把这条序列里若干步骤做成了 3 个互相重叠的子系统（后处理、section 过滤、结构化导出契约）。结果是：IR *原语*共享了，*序列*却重复 4 份并各自漂移；同时累积了一批"接线但未通电"的特性（`--remove-inline-citations`、`cache/`、`citations/`、`schemas/structured`）和一块约 1900 行的僵尸模块（`latex/parser.py`）。

重构的主导思想因此很明确：**一个编排器，源策略可插拔；IR 是唯一中间表示；Emitter 拥有最终输出；显式依赖、Fail Fast、Schema 即契约。**

## 一、项目定位与设计意图

**定位**：arXiv 论文 → Markdown 转换工具。支持远程 HTML / 远程 LaTeX / 本地 HTML 文件 / 本地归档（tar.gz）四类输入；图片下载与 PDF→PNG 转换并插入；元数据富化（arXiv API / Crossref / TeX 机构信息）；结构化 JSON 导出（`paper.{meta,document,assets,bib,graph}.json`）。

**显式的设计意图**（从代码与 README 推断）：

1. **IR 三层编译器架构**：前端 `Builder`（格式 → `DocumentIR`）→ 中端 `Transform`（`DocumentIR → DocumentIR`）→ 后端 `Emitter`（`DocumentIR` → Markdown / JSON / 纯文本）。这是正确且现代的选择，应作为**主导架构**被贯彻到底。
2. **类型健全的数据层**：Pydantic v2 discriminated union + `extra="forbid"`。
3. **多源统一**：4 种输入应产出同一形态，仅"取源"步骤不同。
4. **CPU 密集步骤卸载到线程**，事件循环在 batch 下推进多篇。
5. **异常带退出码**：`Arxiv2mdError(exit_code)` 体系。

**连贯性问题**：意图 1/3 只落到"原语层"，没落到"编排层"。这是当前所有结构性问题的根。

## 二、当前架构与数据流程（已核对的真实状态）

### 2.1 路由：统一入口，4 路分支

`cli/runner/convert.py:28-42` 的 `run_convert_flow` 是唯一路由器，按输入类型 4 路分支：

| 输入 | 分支 | 处理函数 | 最终代码路径 |
|---|---|---|---|
| 本地 HTML 文件 | `convert.py:34` | `_process_local_html` | `ingest_local_html` → **HTMLBuilder** |
| 本地归档 | `convert.py:36` | `_process_local_archive` | `ingest_local_archive` → 自动探测 **LaTeX/HTML Builder** |
| 远程 + `--parser latex` | `convert.py:40` | `_process_arxiv_paper` | `ingest_paper` → `ingest_paper_latex` → **LaTeXBuilder** |
| 远程 HTML（默认） | `convert.py:42` | `_process_arxiv_paper_ir` | `IngestionOrchestrator.run()` → **HTMLBuilder** |

4 路最终都汇聚到 `cli/output_finalize.py:148 finalize_convert_output`。**前序评审担心的"IR 只服务 1/4"已不成立——4/4 都在 IR 上。** `output/formatter.py`、`html/markdown.py`、`ir/_legacy_blocks.py` 均**已删除**（核对：文件不存在，0 导入者）。

### 2.2 编排：4 份并行实现（核心事实）

`IngestionOrchestrator.run()`（`ingestion/orchestrator.py:97-116`）只是 4 条路径之一。另外 3 条（`ingest_local_html`、`ingest_paper_latex`/`_ingest_paper_latex_impl`、`ingestion/local.py:_ingest_{latex,html}_archive`）**各自重新编排同一序列**：

```
取源 → 建 IR(builder) → 跑 PassPipeline → (split_ir_sections + emit×3) →
format_markdown_output → save_paper_metadata → write_bundle(JsonEmitter)
```

**证据**：
- "emit + split + format_markdown_output"的 ~12 行块在 **5 处**逐字重复：`orchestrator.py:388-416`、`latex.py:216-230`、`local.py:239-252`、`local.py:433-446`、`local_html.py:131-144`。
- `PassPipeline` 在 **5 处**手工组装，且**构成漂移**（见 §三-H）。
- `format_markdown_output` 在 6 处被调（orchestrator + latex + local×2 + local_html）。

这是当前**最大的复杂度来源**：不是死代码，而是"活代码的 4 份拷贝"。任何对序列的修改都要改 5 个地方，漏改即静默漂移。

### 2.3 Markdown 后处理：2 层、2 个架构层（可收敛为 1）

| 层 | 函数 | 位置 | 调用点 | 职责 |
|---|---|---|---|---|
| A | `format_markdown_output` | `output/markdown_utils.py:111-143` | 每条 ingest 路径 emit 后（5 处，每篇调 3 次） | 锚点换行、表格标题、display-math 简化、bullet 去重、空行压缩 |
| B | `apply_markdown_postprocessing` → `clean_markdown_output` | `output/markdown_postprocess.py:124-172` | `cli/output_finalize.py:193`（每篇 1 次，对 content/refs/appendix 各跑） | 剥 `<a id>`、清数学 LaTeX、`$x$` 间距 |

前序评审说的"3 重"现已收敛为"2 重"。但两层**职责重叠**（都做锚点 + 数学 + 空行），且分布在两个架构层（ingest 层做 A，CLI finalize 层做 B），无法整体推理。Emitter 按构造就**不拥有最终输出**——它产出的 markdown 必须再被两层正则修补。

### 2.4 做对的部分（须保留）

- **IR 数据层类型健全**：`extra="forbid"` 单点配置（`ir/core.py:35`），无 mutable default 共享（全用 `Field(default_factory=list)`）。
- **IR 是干净的中层**：`ir/` 下**零**导入 `html/latex/output/network`（核对：grep 无命中）。
- **异常体系**：10 个 `Arxiv2mdError` 子类，语义清晰。
- **`MarkdownEmitter` 对未知类型 `raise EmitterError`**（`ir/emitters/markdown.py:122,171`）——不静默丢。
- **图片异步路径**：`process_images_async` 用 `ProcessPoolExecutor` + `finally: shutdown` + 信号量（`images/processor.py:186-247`），正确。
- **`IngestionOrchestrator` task 泄漏已修**：`_fetch_html_and_metadata` 在 metadata_task 失败时 cancel 并 await 孤儿 html_task（`orchestrator.py:146-160`）。
- **`ConvertParams` 是 `frozen=True` dataclass，`merge_convert_params` 用 `dataclasses.replace`**（`cli/runner/base.py:10-18`）——前序 A1 已修。

## 三、核心问题（按严重度排序）

### A. 编排在 4 条路径上重复（结构复杂度之根）

见 §2.2。4 份手写编排 + 5 处 emit-split 块 + 5 处 pass 组装。**没有 `default_pipeline()` 工厂**（`ir/transforms/__init__.py:3-7` 仅 re-export）。后果：改序列要改 5 处；漂移已发生（见 H）。

### B. "接线但未通电"的特性（Fail Fast 的反面：声明了却不生效）

| 特性 | 证据 | 状态 |
|---|---|---|
| `--remove-inline-citations` | 被 `schemas/query.py:25,44,63`、`cli/params.py:21`、`cli/app.py:157,249,318,426`、`cli/runner/convert.py:72,146,187`、`ingestion/local.py`、`ingestion/pipeline.py:23,98` 一路透传；但 `IngestionOrchestrator` 从不读 `self.params.remove_inline_citations`；任何 builder/emitter 都不消费它 | **静默 no-op**——用户设了无效果 |
| `cache/result_cache.py`（348 LOC） | `ResultCache` / `get_result_cache` / `CacheKey` / `CachedResult` **全部 0 内部调用者**；`IngestionOrchestrator.run` 不调 cache.get/set | 整模块死；仅 `config cache` 子命令可能引用 |
| `citations/`（resolver 282 + formatter 196 LOC） | `CitationResolver` 0 外部调用者；`resolve_citations` 仅被同文件 `export_bibtex` 调；`export_bibtex` 仅被 `cli/app.py:629`（`bibtex` 子命令）调 | `convert` 流程**完全不解析引用**；README 宣称的"元数据富化"在 convert 路径不成立 |
| `schemas/structured.py`（11 个 Pydantic 模型） | `PaperMetaJson`/`PaperDocumentJson`/`BlockJson`/… 在 `src/` 内** 0 实例化**；`JsonEmitter` 用 `b.model_dump(exclude_none=True)` 手搓 dict | 模型 = 仅文档；JSON 输出无运行时校验 |

**`--remove-inline-citations` 是真实用户可见 bug**：flag 存在、文档列了、却什么都不做。这违反 Fail Fast——非法/无效输入应在入口拒绝，而非静默吞掉。

### C. 僵尸模块 `latex/parser.py`（1990 LOC，约 95% 死）

`parse_latex_to_markdown`（`latex/parser.py:69`）= 0 内部调用者（仅 `latex/__init__.py` 导出 + 注释提及）。活 LaTeX 路径走 `ir/builders/latex.py:LaTeXBuilder.build`，直接 `pypandoc.convert_text`（`ir/builders/latex.py:146,155`），**绕过整个 `latex/parser.py`**。

该模块存活的真实符号仅 2 个：
- `_resolve_latex_includes`（被 `ingestion/latex.py:166`、`ingestion/local.py:202` 懒加载导入，活）
- `ParserNotAvailableError`（异常，被 3 处导入）

其余约 40 个函数（front-matter 抽取、include 递归、markdown 修正、图片处理、章节抽取、参考文献、美化）全是前 IR 时代的 pandoc 后处理管线，已被 `LaTeXBuilder` 取代。**约 1900 LOC 死代码。**

### D. 4 个进程级可变单例 + lookup 式注入

| 单例 | 位置 | 被谁 lookup |
|---|---|---|
| `_SETTINGS` | `settings/loader.py:17` | orchestrator:69、cache、http:26、fetch:55、arxiv_api:137、crossref_api:65、author_enrichment:135、images/processor:99、metadata_tex:37 |
| `_client`（httpx） | `network/http.py:15` | 全 network/ |
| `_result_cache` | `cache/result_cache.py:337` | （无调用者，见 B） |
| `_encoding`（tiktoken） | 缓存层 | output/markdown_utils |

`IngestionOrchestrator.__init__` 在 `orchestrator.py:69` 调 `get_settings()`——**依赖靠全局查找而非参数注入**。后果：测试必须 `reset_settings_cache()+set_settings(...)` 才能注入夹具；`asyncio.to_thread`（orchestrator:107-111 大量使用）跨线程依赖 GIL 且不可并发变配置；batch 无法 per-paper 配置。违反"显式优于全局"。

### E. Emitter 不拥有最终输出（见 §2.3）

2 层后处理分布在 ingest 层（A）与 CLI finalize 层（B），Emitter 产出仍需修补。锚点在 A 加换行、在 B 删标签——同一意图两处实现，顺序敏感。

### F. 防御性吞异常（Fail Fast 反面）

`IngestionOrchestrator` 反复 `except (OSError, ValueError, TypeError, RuntimeError): logger.warning(...); continue`：
- `orchestrator.py:243-244`（图片处理失败）
- `orchestrator.py:261-262`（TeX 抓取机构信息失败）
- `orchestrator.py:493-494`（paper.yml 保存失败）
- `orchestrator.py:517-519`（结构化 JSON 导出失败）
- `output/metadata_tex.py:45-47,89-91`（TeX 机构合并失败）
- `citations/resolver.py:165-167`（`except Exception`）

这些把"程序员错误/配置错误/环境错误"降级为 warning 继续跑，**隐藏非法状态**。Fail Fast 要求：可恢复的网络错误→重试后明确报错；不可恢复的配置/编程错误→入口拒绝并明确退出码。

另有 **5 处裸 `raise ValueError/RuntimeError`**（`output/metadata.py:112,117,125,132`、`html/parser.py:18`）绕过 `Arxiv2mdError(exit_code)`，以 traceback + exit 1 暴露给用户。

### G. `JsonEmitter` 绕过 schema 契约 + SCHEMA_VERSION 双源

- `ir/emitters/json_emitter.py:23` `SCHEMA_VERSION = "2.0"`；`schemas/structured.py:9` `SCHEMA_VERSION = "1.0"`。**两个真值源**。
- `JsonEmitter` 用字符串模板 `f"{sid}:b{bi}:{blk.type}"` 拼 id（`json_emitter.py:82,98`），不经过任何 `Paper*Json` 模型。schema 与输出**无运行时绑定**，dict 漂移即契约静默破坏。
- `_section_to_dict` 与 `_flatten_section_blocks` 重复同一 id 模板。

### H. Pass 管线无单一来源 + `SectionNumberingPass` 不对称（已发生的漂移）

5 处手工组装 pass，**构成不一致**：

| 路径 | pass 序列 | 备注 |
|---|---|---|
| orchestrator（HTML） | `SectionFilter? → Numbering → FigureReorder → Anchor` | |
| latex.py | `SectionFilter → Numbering → **SectionNumbering** → FigureReorder → Anchor` | 唯一加 SectionNumbering |
| local_html | `SectionFilter → Numbering → FigureReorder → Anchor` | |
| local.py（LaTeX 归档） | `Numbering → FigureReorder → Anchor`（无 filter） | **缺 SectionNumbering** |
| local.py（HTML 归档） | `SectionFilter → Numbering → FigureReorder → Anchor` | |

`SectionNumberingPass`（给 LaTeX 章节标题加 `1.2.3` 前缀）只在远程 LaTeX 路径加，**本地 LaTeX 归档路径不加** → 两条 LaTeX 路径**编号不一致**。这正是编排重复的直接后果。

另有顺序敏感隐患：`FigureReorderPass` 依赖 `NumberingPass` 填的 `figure_id`（`figure_reorder.py:55,69` 假设 `figure-N`）；`AnchorPass` 须最后。手工组装一旦顺序错即静默错。

### I. 类型安全缺口

- **Visitor**（`ir/visitor.py`）：`getattr(self, f"visit_{node.type}", self.visit_default)`（`:75-85`）字符串派发；`_CHILD_SPECS`（`:40-63`）手维护 dict，与 union 定义**无编译期绑定**；新容器节点未注册 → `walk()` **静默跳过子节点**。

## 五、重构方案（破坏性，目标架构）

### 5.1 设计原则（统一思想）

1. **单一编排，源策略可插拔**：`IngestionOrchestrator` 持一个 `Source` 策略；4 种输入 = 4 个 `Source` 实现，只负责"取源 → 产出 `DocumentIR + PaperMetadata + assets`"。下游 transforms/emit/save/export **只有一条路径**。
2. **IR 是唯一中间表示**：Builder 产 IR，Transform 纯 IR，Emitter 走 IR 不回 parse（已基本达成，保留）。
3. **Emitter 拥有最终输出**：markdown 格式化**只在 emitter 内做一次**；删除 finalize 层与 ingest 层的重复后处理。
4. **不可变 Pass**：Pass 返回新 IR（或显式 deepcopy）；管线可安全重跑。单一 `default_pipeline()` 工厂。
5. **显式优于全局**：settings / http client 由构造函数注入；core 路径不调全局 lookup。
6. **Schema 即契约**：`JsonEmitter` 输出经 `schemas.structured` 模型校验（或删除模型，二选一，不留中间态）。
7. **Fail Fast**：接线未通电的特性——**要么实现，要么删除**，不留 no-op flag；非法状态在入口拒绝；区分"可重试的网络错"与"不可恢复的配置/编程错"。
8. **奥卡姆剃刀**：删僵尸模块；不新增"为未来"的抽象层。

### 5.2 目标目录结构


## 六、分阶段重构计划（每阶段独立可提交、可回归）

### Phase 0 — 安全网（先做）
- 固定 markdown golden snapshot：HTML（一篇远程）、LaTeX（`tests/fixtures/sample_paper.tex`）、local HTML 各一，存 `tests/golden/`。
- 锁基线：`pytest`（343）、`ruff`（src 6）、`mypy`（17，全在 `ir/builders/latex.py` + `network/arxiv_abs_html.py`）。
- 回归 oracle：测试数不降、lint/type 不退化。

### Phase 1 — 通电或拔线（Fail Fast，高 ROI 低风险）
1. `--remove-inline-citations`：**实现**（在 `MarkdownEmitter` / `SectionFilterPass` 消费该 flag 剔除内联引用）**或从 CLI/schema 全链路删除**。禁止维持 no-op。
2. `cache/`：接入 `IngestionOrchestrator`（run 起点 cache.get，结束 cache.set），**或删 `result_cache.py`**。接入则修 `_create_cache_key` 工厂使其接受全部影响输出的 flag。
3. `citations/`：决定 `convert` 是否解析引用。是→orchestrator 调 `CitationResolver`；否→README 删除"元数据富化"中 convert 路径的引用解析表述，`citations/` 降为 `bibtex` 子命令专用。

### Phase 2 — 删僵尸代码（减负）
1. `latex/parser.py`：抽 `_resolve_latex_includes` + `ParserNotAvailableError`，删余 ~1900 LOC；同步删 `latex/__init__.py` 的 `parse_latex_to_markdown` 导出与 `tests/test_integration_with_mocks.py` 的 legacy 用例。
2. `schemas/structured.py`：接 JsonEmitter 校验（Phase 6 做则此步先标记）**或删**。
3. `images/processor.py` 同步 `process_images`：删。
4. 重新生成 `egg-info/SOURCES.txt`（清 `_legacy_blocks.py` 残留）。

### Phase 3 — 统一编排（最大结构收益）
1. 引入 `Source` 协议：`fetch() -> (DocumentIR, PaperMetadata, AssetBundle)`，4 实现（Html/Latex/LocalHtml/LocalArchive）。
2. `IngestionOrchestrator.run` 改为：`source.fetch() → run_transforms → emit → save → export`，单一序列。
3. 删 `ingest_local_html` / `_ingest_paper_latex_impl` / `local._ingest_*_archive` 中的编排逻辑，改为各自 `Source`。
4. 消除 5 处 emit-split 块 → 收敛进 orchestrator 的 `_emit_split`。

### Phase 5 — Emitter 拥有输出（收敛后处理）

## 十、总结

前序重构把"IR 三层"做成了项目的**中间表示标准**，这是对的且已基本完成。但**编排层从统一**这一步从未走出：4 条输入路径各自手抄同一序列，并在此过程中长出了 3 个重叠子系统（后处理、过滤、导出契约）和一批"接线未通电"特性。当前 18k LOC 里约 2.4k 是僵尸/死代码，约 0.6k 是重复实现，但这些只是症状；**根因是缺少"一个编排器 + 可插拔源策略"这一主导架构**。

本方案不新增抽象层，而是**收敛**：一个编排器、一条管线工厂、一个后处理点、一个 schema 真值源、一种依赖注入方式。配合 Fail Fast（通电或拔线、入口拒绝非法状态）与奥卡姆剃刀（删僵尸），目标是把项目从"IR 原语统一、编排四份漂移"推进到"**单一连贯管线**"。
