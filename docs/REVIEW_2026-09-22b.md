| BatchManifestRecorder O(n²) | `output/manifest.py:121-166`：`flush()` 对全部 entries 全量 json.dumps+重写，且是**同步 IO 在事件循环上**（batch 每条 record 触发）。n=1000 → ~150MB 写 + 数秒 loop 停顿。改节流 flush + `to_thread` |

## 七、系统性根因（写给下一次重构）

1. **builder 急切丢弃不可再生信息**（C1、C2、G2-4、I-8 同根）：翻译/推导一旦在 builder 做掉，拥有全局视野的 pass 就再也修不回来。原则应写入 `ir/builders/base.py`：**builder 只保真，翻译留给 pass**。
2. **同类防御只堵单入口**（C6 vs A4、G3-4 vs zip-slip、G4-1）：每轮审计都在补"另一个入口"。修复时应先枚举同函数/同机制的全部调用点，回归测试按调用点矩阵设计。
3. **转义知识仍有语法位盲区**：escapes.py 单源化只覆盖了 audit4 已知的四位；行首位（G2-2）、fence 长度（G2-1）、code 定界（G2-3）、HTML attr（I-11/I-1）是下一批应收编的位。
4. **五份手写树遍历器覆盖面各不相同**（numbering.py 的 prescan/collect/number/sweep/sweep_links，I-5 的根源）：`ir/visitor.py` 的 `_CHILD_SPECS` 已是现成单源，transforms 应改用统一 `walk()`。
5. **对抗性 fixture 缺失是历轮 P1 逃过 golden 的共同根因**（audit4 原话 + 本轮 C1-C6 全部不在 fixture 中）：建议建立 adversarial corpus——特殊字符标题/重名图片/注释掉的条件块/verbatim/Div 多块/ol start/rowspan/CJK 长标题/algo 浮动体，一次入 golden 永久守护。
6. **事件循环上的同步 IO 残留**（§四 X8/X9 + manifest）：audit4 下放了三处，剩余点应清单化收口（统一 async teardown 上下文管理器仍是 09-20 轮的建议，未做）。
